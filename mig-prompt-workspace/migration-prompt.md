## Current Application Summary

`coolstore-monolith` (`com.redhat.coolstore:monolith:1.0.0-SNAPSHOT`) is a small Java EE 7 e-commerce monolith. It is packaged as `ROOT.war` and targets JBoss EAP 7.4, with some WebLogic leftovers. The backend is a layered JAX-RS/CDI/EJB/JPA application with 30 Java files in the `model`, `persistence`, `rest`, `service` and `utils` packages. There are also 3 `weblogic.*` stub classes, which exist only so the code compiles without WebLogic. The REST API sits under `/services`. An AngularJS 1.x + PatternFly single-page UI in `src/main/webapp` (`app/`, `partials/`, `index.jsp`, plus vendored `bower_components`) calls it. Optional Keycloak login is done in the browser by the Keycloak JS adapter (`keycloak.json`, realm `eap`, public client `eap-app`). The backend itself does not enforce authentication.

Checkout publishes the cart as JSON to the JMS topic `topic/orders`. `OrderServiceMDB` consumes it, persists the `Order` and decrements inventory. `InventoryNotificationMDB` is a hand-wired WebLogic t3/JNDI subscriber that logs low-stock warnings. Shipping cost is calculated by `ShippingService`, a `@Stateless @Remote` EJB that `ShoppingCartService` looks up through remote JNDI (`ejb:/ROOT/ShippingService!...`), even though it runs in the same JVM. Flyway 4.1.2 runs the `db/migration` scripts (V1_1 schema, V1_2 data) from a `@Singleton @Startup` EJB against `java:jboss/datasources/CoolstoreDS`. `OrderService` creates a `FileSystemAuditLogger` from the in-house `audit-logging-library` 1.0.0, which is a `system`-scoped jar in `lib/`.

The cart is held in a `@Stateful` `ShoppingCartService` with a single `ShoppingCart` field that ignores `cartId`. It is injected into a `@SessionScoped` `CartEndpoint`, and `web.xml` declares `<distributable/>`, which turns on HTTP session replication. Konveyor finding `session-00000` (mandatory) flags this as not cloud-ready.

**Technology Stack:**
- Java 8 source/target (maven-compiler 3.0), Maven, WAR packaging, `maven.test.skip=true`, no tests at all
- Java EE 7: JAX-RS 2.0, CDI 1.1 (`bean-discovery-mode=all`), EJB 3.2 (`@Stateless`, `@Stateful`, `@Singleton @Startup`, `@MessageDriven`, `@Remote`), JPA 2.1 (persistence unit `primary`, JTA), JMS 2.0, JSON-P, javax.rmi `PortableRemoteObject`

- `com.enterprise:audit-logging-library:1.0.0` (system scope). `lib/audit-logging-library-2.0.0.jar` is also present
- Keycloak 'eap' realm (`realm-export.json`), used through the browser JS adapter
- UI: AngularJS, PatternFly, bower-vendored JS; `index.jsp` / `health.jsp` use JSP scriptlets

**Architecture:**

## Migration Approach

**Strategy:** Big bang, single-module, in-place conversion on the migration branch.

**Reasoning:** The app is small (30 Java files, one deployable), there are no external consumers apart from the bundled UI, and the source branch stays available for rollback. A strangler fig would add proxy and dual-runtime cost with no benefit. Risk is controlled with characterization tests that pin the REST contract and pricing rules before and after the change.

**Key Considerations (design decisions):**
1. **Namespaces/build:** Change `javax.*` to `jakarta.*`. Convert the WAR to a Quarkus jar, set Java 21 (`maven.compiler.release=21`) and re-enable tests by removing `maven.test.skip`.
2. **EJBs → CDI:** `@Stateless` becomes `@ApplicationScoped` with `@Transactional` on write methods. `@Singleton @Startup` goes away (Flyway is handled by the extension). `@Stateful` is removed. `@MessageDriven` becomes `@Incoming`.
3. **Remote EJB:** Delete `ShippingServiceRemote` and the JNDI lookup. `ShippingService` becomes an `@ApplicationScoped` bean injected into `ShoppingCartService`. The interface may stay as a plain local interface.
4. **Messaging: SmallRye Reactive Messaging with in-process channels.** `ShoppingCartOrderProcessor` uses `@Channel("orders") Emitter<String>`, and `OrderServiceMDB` / `InventoryNotificationMDB` become `@Incoming("orders")` consumers (`@Broadcast` gives topic semantics). *Why:* producer and consumers already live in one JVM, and the old JMS topic gave no durability across a single node, so a broker would only add infrastructure (AMQ/Kafka operators) without changing behaviour. The channel names and JSON payload stay as they are, so a later move to `quarkus-messaging-amqp` (Red Hat AMQ Broker) or `quarkus-messaging-kafka` (AMQ Streams) needs only config (`mp.messaging.outgoing.orders.connector=...`). Order persistence runs in a `@Transactional` blocking consumer (`@Blocking`).
5. **Persistence:** Remove `persistence.xml` and `Resources`, inject `EntityManager` directly, and configure `quarkus.hibernate-orm.*` with `database.generation=none`. Keep the entities and table names, and keep `hibernate_sequence`-compatible ID generation as defined in V1_1.
6. **Flyway:** Use `quarkus-flyway` with `migrate-at-start=true` and `baseline-on-migrate=true`, keeping the existing `db/migration` scripts. Delete `DataBaseMigrationStartup`.
7. **Datasource:** Use `quarkus.datasource.jdbc.url=jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:coolstore}`, with the username and password taken from env vars. The test profile uses H2 (PostgreSQL mode) or Dev Services.
8. **Session/cart (Konveyor session-00000):** Remove `web.xml` together with `<distributable/>`. `CartEndpoint` becomes stateless (`@ApplicationScoped`/default). `ShoppingCartService` becomes an `@ApplicationScoped` store backed by a `ConcurrentHashMap<String, ShoppingCart>` keyed by `cartId`, which also fixes the existing bug where `cartId` was ignored. This keeps state out of the HTTP session so any pod can serve any request as long as carts are externalized. As a first step it runs with 1 replica (or Route sticky cookies). The plan must document the follow-up of an Infinispan/Data Grid or Redis cart store behind a `CartStore` interface.
9. **Audit logging (rules audit-logging-0001..0005):** Upgrade to 2.0.0. The library needs Java 21. Install `lib/audit-logging-library-2.0.0.jar` into the build's local repo (`maven-install-plugin` `install-file` bound to `validate`, or a file-based in-project repo) rather than using `system` scope. The 1.0.0 jar can then be removed. Replace `FileSystemAuditLogger` with `StreamableAuditLogger(AuditConfiguration)` configured with `setStreamProtocol("TCP")`, `setStreamHost(${AUDIT_STREAM_HOST})` and `setStreamPort(${AUDIT_STREAM_PORT})`. Build events with the record constructor `new AuditEvent(Instant timestamp, String eventType, String userId, String sessionId, String application, String component, String action, String resource, AuditResult result, String message, Map<String,Object> details, String correlationId, String sourceIp, String userAgent)`, emit them with `logEventAsync(event)` (returns `CompletableFuture<Void>`), and never use `builder()`, `logEvent`, `logSuccess` or `logFailure`. Audit order persistence (`ORDER_CREATED`, SUCCESS/FAILURE). The logger must be lazily connected and failure-tolerant (`logEventAsyncSafe` or exceptionally-handled futures) so the app still starts and tests still pass when no TCP collector is present. Jackson jsr310 comes from the Quarkus BOM.
10. **Auth (Keycloak → quarkus-oidc):** Add `quarkus-oidc` as a `service` application validating bearer tokens from the `eap` realm (`quarkus.oidc.auth-server-url=${OIDC_AUTH_SERVER_URL}/realms/eap`, `client-id=eap-app`). Keep today's behaviour: all `/services/*` endpoints stay anonymous (permit), so the UI works with or without SSO. Tokens are verified when they are presented. OIDC is switched on/off with `quarkus.oidc.tenant-enabled=${OIDC_ENABLED:false}` (disabled in tests). The browser keeps using the Keycloak JS adapter, with `keycloak.json` served statically and its `auth-server-url` externalized.
11. **UI:** Move `src/main/webapp/**` (minus `WEB-INF`) to `src/main/resources/META-INF/resources`. Convert `index.jsp` to `index.html`, since Quarkus has no JSP. Replace `health.jsp` with SmallRye Health at `/q/health`, optionally adding a static `/health` alias. Keep `coolstore.json` and `bower_components`, and keep the relative `/services/...` base URLs.
12. **WebLogic cleanup:** Delete `src/main/java/weblogic/**`. `StartupListener` becomes `@Observes StartupEvent/ShutdownEvent`. Remove the t3 JNDI, `PortableRemoteObject` and `javax.rmi`/JMS spec dependencies.
13. **Logging:** Either keep the JUL `Logger` producer (it works with JBoss LogManager) or switch to `org.jboss.logging.Logger`. Replace `System.out` with a logger.
14. **Data migration:** None. The schema and seed data are unchanged and managed by Flyway; for an existing DB, Flyway baseline-on-migrate applies.

## Constraints and Risks

**Constraints:** Autonomous run with no stakeholder input. java/mvn/podman/oc are not preinstalled (JDK 21 + Maven are fetched into `/tmp` to verify; images and the cluster can only be validated statically). No timeline was given.

**Risks & mitigations:**
| Risk | Mitigation |
|---|---|
| Audit lib 2.0.0 uses a TCP socket; with no collector, startup or requests could fail | Lazy/tolerant init, `logEventAsync` with `exceptionally` logging, config via env, test with an embedded ServerSocket |
| Audit lib needs jackson 2.13 / slf4j 1.7; possible conflicts with the Quarkus BOM (Jackson 2.17) | Let the BOM manage versions; integration test that serializes `AuditEvent` with Instant |
| In-memory cart map loses carts on restart and does not share them across replicas | Document it; replicas=1 or sticky Route; follow-up `CartStore` on Data Grid/Redis |
| In-process messaging loses in-flight orders on crash (same as before on a single node) | Accepted; config-only path to AMQP/Kafka is documented |
| JSON contract drift (Jackson vs JSON-B/Yasson field naming, nulls, `double` formatting) | REST Assured contract tests on field names; keep the getter-based POJOs |
| `@GeneratedValue` strategy differences in Hibernate 6 vs the V1_1 `hibernate_sequence` | Pin the generator explicitly (sequence `hibernate_sequence`, allocationSize 1) and test order persistence |
| JSP removal breaks the UI bootstrap (`index.jsp` scriptlet) | Convert to static `index.html`; smoke-test that `/` loads |
| Keycloak URL hard-coded to localhost:8081 | Externalize; OIDC disabled by default |
