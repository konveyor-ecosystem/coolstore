## Current Application Summary

**Coolstore** is a small Java EE 7 e-commerce demo packaged as one WAR (`ROOT.war`). It targets JBoss EAP / WildFly and still contains WebLogic remnants. It exposes a JAX-RS REST API under `/services/*` (products catalog, shopping cart with promotions and shipping calculation, orders). An AngularJS 1.x / PatternFly single-page UI under `src/main/webapp` consumes that API. Checkout publishes the cart as JSON to the JMS topic `topic/orders`. A message-driven bean (`OrderServiceMDB`) consumes the topic, turns the JSON into an `Order` entity and persists it with JPA. A second listener (`InventoryNotificationMDB`) connects to a WebLogic server over `t3://` JNDI and logs low-inventory messages. A Flyway 4 `@Singleton @Startup` bean creates the schema and loads seed data through a container-managed `@Resource` DataSource. Order processing is audited with the proprietary `audit-logging-library` 1.0.0 (`FileSystemAuditLogger`).

The application uses many server-provided features: EJB pooling and transactions, a remote EJB JNDI lookup of `ShippingService` from inside the same WAR, JMS resources bound in JNDI, `<distributable/>` HTTP-session replication and a `@SessionScoped` REST endpoint. These features block running it as a stateless, horizontally scalable container on OpenShift, and Konveyor flags them.

## Migration Approach

**Strategy:** Big bang, as a single-pass refactor on a migration branch, done in ordered internal steps with a green build after each step.

**Reasoning:**
- The app is small (30 Java files, 1,785 LOC) and `max_blast` is 0 for every Java package, so the changes are tightly scoped.
- The `javax`→`jakarta` switch and the WAR→Quarkus packaging change break the build all at once. Running both runtimes side by side for a strangler fig would cost more than it saves.
- Risk tolerance is moderate. We keep the same REST contract and UI, put characterization tests in front of the business logic, and keep the legacy WAR build tagged so we can roll back.

**Internal step order** (follows `migration_plan.json` package ranking and the compile dependencies):
1. Baseline and characterization tests: record pricing/promo/shipping behaviour and the REST contract.
2. Build foundation: Quarkus 3.15 BOM, Java 21, extensions, audit library 2.0.0 installed, `application.properties`.
3. Model and persistence: `jakarta.persistence`, Hibernate ORM config, Flyway at start, delete `persistence.xml`/`Resources`/`DataBaseMigrationStartup`.
4. Services: EJB→CDI, ShippingService injection, cart store, audit logging 2.0.0.
5. Messaging: Reactive Messaging `orders` and `inventory` channels; delete JMS, WebLogic and stub code.
6. REST and web: quarkus-rest, JSON-P, static UI move, health, delete web.xml/JSPs.
7. Test suite: unit tests plus `@QuarkusTest`/RestAssured, coverage.
8. Containerization: UBI 9 OpenJDK 21 Containerfile.
9. OpenShift deployment manifests.
10. CI and documentation.

**Key Considerations:**
- **Transactions:** EJB methods are transactional by default. CDI beans are not. Add `@Transactional` explicitly to `OrderService.save`, the order consumer, and any write path.
- **Cart state:** `@Stateful` plus `@SessionScoped` with `<distributable/>` becomes an in-memory `CartStore` keyed by cartId. State is lost if a pod restarts, and replicas do not share it. With replicas > 1 the Route needs sticky sessions (`haproxy.router.openshift.io/balance: source`, or the default cookie), until a later move to Infinispan/Data Grid or Redis. This is a known, accepted limitation.
- **Messaging semantics:** JMS topic delivery becomes an in-memory channel. Delivery is in-process and not durable. The AMQP connector can be enabled with `%prod` config without changing code. The order consumer is blocking JPA work, so use `@Blocking` (or `@Transactional` on the worker thread).
- **WebLogic inventory feed:** The t3 integration is dropped. The `inventory` channel stays as an extension point that is in-memory by default and can be mapped to AMQP.
- **Data:** No data is migrated. Flyway V1_1/V1_2 scripts are reused unchanged. Check that both scripts run on H2 (dev/test) and on PostgreSQL (prod), for example sequence and type syntax. Flyway 4 → Flyway 10 (managed by Quarkus) keeps the existing history table name `flyway_schema_history`. The old `schema_version` table matters only for existing databases (none assumed).
- **Audit logging 2.0.0:** Without a TCP collector, a failed connection must not break checkout. Catch and log `AuditLoggingException`, and make host/port configurable (`AUDIT_STREAM_HOST`, `AUDIT_STREAM_PORT`).
- **JSON:** The UI expects the current JSON field names of `ShoppingCart`, `Product` and `Order`. Jackson must serialise the same shape as before; the RestAssured contract tests check this.
- **Static assets:** About 1,200 vendored files are moved with `git mv`, without edits. Update `coolstore.json`/`keycloak.json` paths only if needed.
- **Secrets:** rgctl flagged 8 potential secrets (for example client-secret entries in `realm-export.json`). No credentials go into images or ConfigMaps. DB credentials come from an OpenShift Secret.
