## Current Application Summary

The Red Hat CoolStore monolith is a small e-commerce application. It is built as a single Maven WAR (`com.redhat.coolstore:monolith:1.0.0-SNAPSHOT`) and deployed on JBoss EAP 7.4 with Java 8. The back end is Java EE 7: EJB 3.2, CDI 1.1, JPA 2.1, JAX-RS 2.0, JMS 2.0 and JSON-P. It exposes a REST API under `/services` with three resources: `/products`, `/cart` and `/orders`. A single-page AngularJS front end (PatternFly, Keycloak JS adapter) is served from the same WAR. On startup, Flyway applies the PostgreSQL schema and seed data.

Checkout works asynchronously. `ShoppingCartOrderProcessor` serialises the cart to JSON and publishes it to the JMS topic `topic/orders`. The MDB `OrderServiceMDB` consumes the message, persists an `Order` and decrements inventory through `CatalogService`. Cart state lives in a `@Stateful` EJB (`ShoppingCartService`) that is held by a `@SessionScoped` JAX-RS resource (`CartEndpoint`). `web.xml` declares `<distributable/>`, which means HTTP session replication. Shipping cost is calculated by a `@Stateless @Remote` EJB (`ShippingService`). The cart looks it up through a WildFly remote-naming JNDI call (`ejb:/ROOT/ShippingService!...`), even though the bean is in the same WAR. `OrderService` creates a file-system audit logger from the proprietary `audit-logging-library` 1.0.0 (system-scoped jar in `lib/`).

rgctl indexed 1,232 files: 35,856 nodes and 125,562 edges. More than 95% of that graph is vendored `bower_components` JavaScript (48 MB), which has no migration impact. The real migration surface is **30 Java files, about 1,785 LOC, in 6 packages**. It is a small monolith with low complexity (avg cyclomatic complexity 1.0, no high-complexity functions).

## Migration Approach

**Strategy:** Big bang, single module. Convert the WAR in place into one Quarkus application and keep the same Maven coordinates.

**Reasoning:**
- 30 Java files / about 1.8 KLOC with low complexity. A strangler-fig setup would cost more than the conversion itself.
- Risk tolerance is moderate and the team is small. A single cutover, with the EAP deployment kept available for rollback, is cheaper than running both stacks for a long time.
- The REST contract and the front end stay unchanged, so clients see no difference.

**Key design decisions:**

| # | Area | Current | Target decision |
|---|------|---------|-----------------|
| D1 | Namespaces | `javax.*` Java EE 7 | `jakarta.*` (Jakarta EE 10 / Quarkus 3), using OpenRewrite/Konveyor recipes or manual edits |
| D2 | Messaging | JMS topic `topic/orders`, `ShoppingCartOrderProcessor` + `OrderServiceMDB` | **SmallRye Reactive Messaging.** `@Channel("orders") Emitter<String>` in the processor; `@Incoming("orders") @Blocking @Transactional` consumer replaces the MDB. **Default: in-memory channel** (no broker to operate). An AMQP 1.0 connector (`quarkus-messaging-amqp`, AMQ Broker) is a documented, profile-driven option (`%amqp` profile). Rationale: the topic was only used in-process; a CDI event would also work, but Reactive Messaging keeps the async semantics and gives an easy upgrade path to a real broker. |
| D3 | Shipping EJB | `@Stateless @Remote ShippingService` via remote JNDI lookup `ejb:/ROOT/...` | Plain `@ApplicationScoped` CDI bean, injected directly. Remove `ShippingServiceRemote` (or keep it as a local interface) and the JNDI lookup. There is no remote client, since the bean is in the same WAR. |
| D4 | Cart state | `@Stateful ShoppingCartService` + `@SessionScoped CartEndpoint`, `<distributable/>` | **Stateless, cartId-keyed cart store.** `@ApplicationScoped CartStore` interface; the default implementation is an in-memory `ConcurrentHashMap<String, ShoppingCart>` (with TTL). The front end already sends `cartId` on every call. This also fixes the bug where `cartId` was ignored. `<distributable/>`/session replication is removed (Konveyor session-00000). For multi-replica HA: either use Route sticky sessions (cookie affinity, the default) or plug in a shared store (Infinispan/Data Grid or Redis) in a later iteration. MVP runs 1-2 replicas with sticky Routes. |
| D5 | Audit logging | `FileSystemAuditLogger` 1.0.0 writing to `./device-inventory-audit-logs` | audit-logging-library **2.0.0**. Use `StreamableAuditLogger` over TCP (host/port from `AuditConfiguration` stream properties, supplied via ConfigMap). Build a full `AuditEvent` record and call `logEventAsync` (rules 0001-0005). Produce it from a CDI `@ApplicationScoped` producer with `@PreDestroy close()`. Add a fail-open/no-op fallback when the endpoint is not configured. Audit `OrderService.save`. Nothing is written to the container file system. |
| D6 | Auth | Keycloak JS in browser (realm `eap`, public client), no server-side checks | Keep the front-end Keycloak JS flow. Make `keycloak.json` and `SSO_ENABLED` configurable per environment. Server side: add `quarkus-oidc` (bearer-token, `quarkus.oidc.tenant-enabled` off by default) to preserve current open-API behaviour. Optionally protect `/services/orders` later. Red Hat build of Keycloak is an external dependency, and `realm-export.json` can be imported into it. |
| D7 | DB migration | `@Singleton @Startup` + Flyway 4 API + JNDI DS | `quarkus-flyway` with `migrate-at-start=true` and the same scripts. `baseline-on-migrate` handles existing DBs: the Flyway 4 `schema_version` table becomes `flyway_schema_history`, and `quarkus.flyway.table` is set or a baseline is documented. Keep `hibernate_sequence` (`@SequenceGenerator(allocationSize=1)` or `hibernate.id.db_structure_naming_strategy=legacy`). |
| D8 | Datasource / JPA | `persistence.xml` with `java:jboss/datasources/CoolstoreDS` | Delete `persistence.xml`. Configure `quarkus.datasource.*` and `quarkus.hibernate-orm.database.generation=none` in `application.properties` (env-var overrides). Inject `EntityManager` directly and remove the `Resources` producer. |
| D9 | EJB → CDI | `@Stateless` services, `@Singleton @Startup`, BMT | `@ApplicationScoped` + `@Transactional` on mutating methods; `@Startup`/`StartupEvent` observers |
| D10 | WebLogic remnants | stub `weblogic.*` classes, `StartupListener`, `InventoryNotificationMDB` (T3) | Delete them. Replace lifecycle logging with `@Observes StartupEvent/ShutdownEvent`. |
| D11 | Front end / JSP | `index.jsp`, `health.jsp` in webapp | Move static assets to `src/main/resources/META-INF/resources`. Convert `index.jsp` into `index.html` (the JSP only created a session). Replace `health.jsp` with SmallRye Health (`/q/health/live`, `/q/health/ready`) and keep a `/health.jsp`-compatible static/redirect if probes reference it. Keep `bower_components` as-is (vendored), with a note to consider pruning. |
| D12 | Logging | JUL `Logger` producer, `System.out` | Keep the JUL producer or switch to JBoss Logging. Replace `System.out` with a logger. JSON logging is optional (`quarkus-logging-json`). |
| D13 | JSON | JSON-P `Transformers` | Keep JSON-P via the `jakarta.json` API (Quarkus provides Parsson) or move to Jackson. The minimal change is to keep JSON-P and verify that the payload contracts are identical. |

**Key Considerations:**
- The JSON shapes of `/services/products`, `/services/cart/*` and `/services/orders` must be byte-compatible for the AngularJS client. Jackson vs JSON-B serialisation differences matter: field names, null handling and double formatting. Characterization tests are required before the cutover.
- Fix the `Order.java` dangling `@Column`. Decide whether `TOTAL_PRICE` is intended; since it is not in the schema, remove it.
- Data: PostgreSQL schema unchanged. Point Quarkus at the existing DB and validate the Flyway history table compatibility (D7).
- Audit library 2.0.0 requires Java 21 at runtime, and it needs a reachable TCP audit collector. Provide config plus a fallback.
- No local build is possible in this sandbox. Every compile, test and image step must run in CI or on OpenShift. Plans must include a "first green build" checkpoint.

## Required Deliverables

### 1. Containerization
- All components must be containerized using Podman/Buildah-compatible `Containerfile`s (`src/main/docker/Dockerfile.jvm` or a root `Containerfile`)
- Multi-stage build: builder `ubi9/openjdk-21` runs `mvn -B package`; runtime `ubi9/openjdk-21-runtime` gets the `target/quarkus-app/` fast-jar layout. Non-root (UID 185 / arbitrary UID compatible), port 8080.
- Security scanning of container images (e.g. Trivy/`roxctl image scan` / Quay scanning) in CI. UBI base images get regular updates.
- Container registry strategy: OpenShift internal registry (ImageStream `coolstore`) for dev/test. Promote to an external Quay registry for prod **[ASSUMPTION]**.
- `.dockerignore`/`.containerignore` excluding `.rgctl/`, `.konveyor/`, `target/`

### 2. OpenShift Deployment
- Kubernetes manifests for all components:
  - `coolstore` Deployment, Service, Route (edge TLS, cookie affinity)
  - PostgreSQL (StatefulSet or Deployment + PVC, or an external DB reference)
  - Optional AMQ Broker (AMQP profile) and audit collector endpoint
  - Kustomize base + overlays (`dev`, `prod`) in `deploy/openshift/`
- Deployment strategy: rolling update (maxUnavailable 0). Blue/green via Route switching for the cutover from EAP.
- Service mesh: not required **[ASSUMPTION]**
- Resource limits: requests 250m/384Mi, limits 1 CPU/768Mi (to be tuned after load test). HPA 1-3 replicas on CPU 70%, only once a shared cart store exists. PDB minAvailable 1.
- Health checks: liveness `/q/health/live`, readiness `/q/health/ready`, startup probe
- ConfigMaps: `application.properties` overrides, audit stream host/port, OIDC URL, `coolstore.json`/`keycloak.json`. Secrets: DB credentials, OIDC client secret if confidential.

### 3. Test Coverage
- **Characterization Tests**: capture current behaviour before migration. These are written against the contract and spec, since the EAP app cannot be run here.
  - Critical user journeys: browse products, then add to cart, update and remove, then checkout, then the order appears in `/services/orders` and inventory is decremented
  - API contracts: JSON shapes/status codes for all `/services/products`, `/services/cart`, `/services/orders` operations (golden JSON files)
  - Data transformation logic: `Transformers` (cart→JSON→Order), `PromoService` rules, `ShippingService` price/insurance tiers (boundary values 0/25/50/75/100/500/10000)
  - Integration points: PostgreSQL via Flyway (Dev Services/Testcontainers), orders channel (in-memory connector), audit logger (fake TCP server)
- **Unit Tests**: minimum **80%** line coverage for migrated service/model code (JaCoCo)
- **Integration Tests**: `@QuarkusTest` + REST Assured for every endpoint, plus messaging and DB
- **End-to-End Tests**: full checkout workflow through the Route on OpenShift (smoke script / Playwright optional)
- **Performance Tests**: baseline target p95 < 300 ms for product list and cart ops at 50 concurrent users. Startup < 5 s (JVM). Memory RSS < 512 MiB. **[ASSUMPTION]**: there is no EAP baseline available in this sandbox, so absolute targets are used.

## Constraints and Risks

**Constraints:**
- Timeline: no hard deadline given **[ASSUMPTION: target ~8-10 weeks]**
- Budget: no additional middleware licences assumed. In-memory messaging by default, so no broker is needed.
- Team: small, limited Quarkus experience
- Environment: the sandbox has no JDK, Maven, container engine or `oc`. All code is validated statically, and build/test/deploy happen in CI/OpenShift.
- Must keep the REST paths, the AngularJS front end, PostgreSQL and the Flyway scripts

**Risks:**
| Risk | Impact | Mitigation |
|------|--------|-----------|
| JSON serialisation drift (JSON-B/Jackson vs EAP RESTEasy defaults) breaks the AngularJS client | High | Golden-file contract tests; explicit Jackson config; keep JSON-P in `Transformers` |
| Cart state lost on pod restart / multi-replica (stateful EJB removed) | Medium | Sticky Routes, 1-2 replicas, documented shared-store follow-up (Data Grid/Redis) |
| In-memory messaging loses in-flight orders on crash (JMS was persistent) | Medium | Document; consumer is transactional; AMQP profile available; optionally make checkout synchronous fallback |
| audit-logging 2.0.0 needs a TCP collector; unknown API details (only bytecode available) | Medium | Wrap in an adapter with config-driven enablement + no-op fallback; verify API with `javap` in CI |
| Flyway 4 → Flyway 10 history table/format mismatch on existing DB | Medium | `baseline-on-migrate`, test against a DB snapshot, `quarkus.flyway.table` config |
| `hibernate_sequence` / ID generation semantics changed in Hibernate 6 | Medium | Explicit `@SequenceGenerator(name, sequenceName="hibernate_sequence", allocationSize=1)` |
| Cannot build locally → late compile errors | Medium | Early "first green build" CI task; small PRs |
| Secrets flagged by rgctl (8) / taint flow (1) | Low-Med | Triage task; move any real credentials to Secrets |
| Keycloak/OIDC misconfiguration blocks UI | Low | `SSO_ENABLED` flag; OIDC disabled by default server side |
